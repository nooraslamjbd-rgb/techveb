**Picture a web page that loads in under 100 milliseconds for a visitor in Tokyo, even though the original server sits in Virginia.**  
That speed is no longer a fantasy; it’s the reality that Amazon CloudFront delivers to sites that have embraced edge‑centric delivery.

## Why CloudFront Still Matters

CloudFront was launched in 2008, and today it powers more than **200 billion requests per month** for AWS customers alone. With **over 200 edge locations** spread across six continents, the CDN can place content as close as a few hops to the end user. For a global retailer, this translates into a measurable drop in cart‑abandonment: a study of a multi‑region e‑commerce platform that migrated to CloudFront saw **latency fall from 320 ms to 85 ms** in the Asia‑Pacific region, boosting conversion rates by 12 percent.

Beyond raw speed, CloudFront offers fine‑grained control over caching, security, and dynamic content delivery—features that have become essential as traffic patterns grow more complex.

## Building a Distribution

1. **Create the distribution**  
   * In the AWS console, choose “Create Distribution” → “Web.”  
   * Point the *Origin Domain* to your S3 bucket or load balancer.  
   * Enable *Static Website Hosting* if you’re serving a single‑page app.

2. **Configure caching**  
   * Set *Minimum TTL* to 0 for highly dynamic data.  
   * Use *Cache Based on Selected Request Headers* to cache different versions for “Accept‑Encoding” or “User‑Agent.”  
   * Enable *Object Caching* for immutable assets: set *Cache-Control* headers on S3 objects to `public, max-age=31536000`.

3. **Security and access control**  
   * Attach an *Origin Access Identity* (OAI) so CloudFront can fetch private S3 content.  
   * Add a *Web Application Firewall (WAF)* rule set to block known bot patterns.  
   * Enable *HTTPS* by attaching an ACM certificate; CloudFront will automatically redirect HTTP to HTTPS.

## Lambda@Edge: Compute at the Edge

Lambda@Edge lets you run Node.js or Python functions in response to CloudFront events: *viewer request*, *origin request*, *origin response*, and *viewer response*. A practical example:

```python
def lambda_handler(event, context):
    request = event['Records'][0]['cf']['request']
    # Block access from a specific country
    if request['clientIp'].startswith('203.'):
        return {
            'status': '403',
            'statusDescription': 'Forbidden',
            'body': 'Access denied'
        }
    return request
```
This snippet can enforce geo‑restrictions before any data leaves the edge, saving bandwidth and improving compliance.

### Common Use Cases

| Use Case | Benefit |
|----------|---------|
| **Dynamic personalization** | Inject user‑specific content based on cookies or headers. |
| **A/B testing** | Serve variant pages from the edge, reducing origin load. |
| **Image optimization** | Resize or format images on the fly with libraries like `sharp`. |
| **Security hardening** | Add custom headers (e.g., `Content-Security-Policy`) or remove sensitive headers. |

## Custom Origins and Origin Failover

If your primary origin is a regional load balancer, set up *Origin Groups* to provide automatic failover. For example, a media streaming service might route to a primary origin in North America and a secondary in Europe. CloudFront will automatically redirect traffic to the secondary if the primary returns a 5xx error.

## Getting Started

1. Sign up for an AWS account and enable the free tier.  
2. Spin up an S3 bucket, upload your static assets, and set appropriate cache‑control headers.  
3. Create a CloudFront distribution, link it to your bucket, and test with `curl -I https://<distribution-id>.cloudfront.net`.  
4. Add a Lambda@Edge function to inject a custom header and redeploy.  
5. Monitor performance via CloudWatch metrics—look for *Average Latency* and *Cache Hit Ratio*.

With CloudFront’s global edge network and the programmable power of Lambda@Edge, you can turn a globally distributed audience into a seamless, ultra‑fast experience—without the overhead of maintaining your own edge infrastructure.
