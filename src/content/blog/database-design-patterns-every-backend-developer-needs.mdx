faq:
  - question: "What is 3NF in database design?"
    answer: "Third Normal Form (3NF) is a design standard that eliminates data redundancy by ensuring non-key attributes depend solely on the primary key."
  - question: "When should you denormalize a database?"
    answer: "Denormalize strategically when read performance requires optimization and complex joins slow down high-traffic backend applications."
  - question: "Why use soft deletes instead of hard deletes?"
    answer: "Soft deletes retain data for auditing, recovery, and reporting by setting a deleted_at timestamp rather than permanently removing rows."
keyTakeaways:
  - "Normalize tables to 3NF by default and denormalize strategically for read performance."
  - "Index columns frequently used in WHERE, JOIN, and ORDER BY query clauses."
  - "Implement soft deletes using a deleted_at timestamp to preserve historical audit data."
  - "Include created_at and updated_at audit columns in every database table schema."
  - "Monitor slow query logs continuously to discover and resolve performance bottlenecks."

<h2>Designing for Production</h2><p>Good database design impacts performance and maintainability.</p><h2>Normalization</h2><p>Normalize to 3NF by default. Denormalize strategically for reads.</p><h2>Indexing</h2><p>Index columns in WHERE, JOIN, ORDER BY. Monitor slow query logs.</p><h2>Soft Deletes</h2><p>Use deleted_at timestamp instead of DELETE. Preserve for auditing.</p><h2>Audit Columns</h2><p>Include created_at, updated_at in every table. Trivial to implement.</p>
