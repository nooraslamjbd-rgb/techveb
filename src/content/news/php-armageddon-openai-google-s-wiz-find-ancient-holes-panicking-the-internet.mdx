The U.S. National Security Agency’s sent out [an alarming warning](https://x.com/NSACyber/status/2112903220209098897) on Wednesday that two critical holes had been found in PHP, with patches already [issued by the PHP Foundation](https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security/).

PHP is a server-side programming language so widely used for web applications that it powers [roughly 70% of the websites](https://w3techs.com/technologies/details/pl-php) on the internet; by some accounts, that’s [more than 33 million sites](https://medium.com/@harishsingh8529/stop-calling-php-dead-it-runs-70-of-the-internet-ec86749d7f0f). It is also used by popular content management systems like WordPress.

The NSA warned that these holes are so severe that if a website can’t be patched immediately, it should be pulled off the web until it can be. The holes allow attackers to infiltrate the server’s file system or a database that may be used by the web app.

Interestingly, these holes have been tucked away in all versions of PHP since version 5, which was released in 2004. Websites not running relatively current versions of PHP will have some updating work to do, as PHP 8.1 and older versions are no longer supported. The recommendation is to update the web server to the current version of PHP, which is 8.5.12.

So how did two such ubiquitous, decades-old flaws that affect nearly every website on the internet suddenly come to light? AI, naturally, particularly via OpenAI and Google’s Wiz.

Security testing company Calif was engaged in OpenAI’s “Patch the Planet” initiative to find flaws in open-source source software. Using GPT‑5.6 Sol, it found one of the flaws, OpenAI disclosed [in a blog post](https://openai.com/index/coordinated-disclosure-of-critical-vulnerabilities/). Separately, the Wiz team also used AI, namely its Wiz Atlas security AI agent, Gemini 4 Argon, and GPT-5.6 Sol to find multiple vulnerabilities in PHP.

Both OpenAI and Wiz followed responsible security research practices and worked with PHP on patches before publicly disclosing the flaws. Then they all worked together to flesh out what they found, and test the patches, drawing in a host of others to help.

Wiz thanked Automattic, Akamai, AWS, Cloudflare, Fastly, Imperva, Microsoft, and Vercel. (While WordPress sites use PHP, WordPress [has issued a statement](https://x.com/WordPress/status/2112907323265917274) saying that the flaw isn’t WordPress specific, and sites running its CMS must patch their servers and work with their web-hosting companies to ensure their sites are protected.)

OpenAI says that these flaws were found by researchers before hackers discovered them. So there were no reports of exploits in the wild. This is also in part because, before AI, these flaws were too hard for hackers to exploit. “With AI this is no longer a barrier. LLMs can help adapt an exploit to different PHP versions, configurations and memory layouts,” [Wiz warned in its blog](https://www.wiz.io/blog/php2shell-php-rce) about the flaws.

In other words, this is the kind of security issue that was found and prevented because of AI, but is also a high risk only because of AI.

Now that the issue has been disclosed, hackers are fully in the know. The race is on for the internet to patch tens millions of websites before hackers can attack the unpatched ones. Hence the NSA’s guidance that if you can’t patch your PHP website right away, you’re better off pulling it offline until you can.
