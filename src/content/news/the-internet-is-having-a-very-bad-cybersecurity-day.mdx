The internet is having a bad day, from a cybersecurity perspective. Government websites around the world [went offline](https://www.reuters.com/world/asia-pacific/eu-agency-warns-websites-may-need-be-taken-offline-php-prepares-patches-2026-10-21/), Reuters reported, after AI discovered [critical security vulnerabilities](https://www.php.net/archive/2026.php#2026-10-21-5) that impacted the [programming language PHP](https://techcrunch.com/2026/10/21/php-armageddon-openai-googles-wiz-find-ancient-holes-panicking-the-internet/). The issues were severe enough that the [U.S. National Security Agency (NSA) advised](https://www.nsa.gov/Press-Room/Press-Releases-Statements/Press-Release-View/Article/4630238/nsa-advisory-php-updates/) organizations using PHP on their systems to either immediately update or take their systems offline until they could.

But [the PHP update](https://techcrunch.com/2026/10/21/php-armageddon-openai-googles-wiz-find-ancient-holes-panicking-the-internet/) wasn’t the only headache cybersecurity folks were facing on Wednesday. [Node.js](https://nodejs.org/en/about), the open-source JavaScript runtime environment, also dropped a security surprise of its own when it [shared](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) that four high-severity [vulnerabilities](https://app.opencve.io/cve/?vendor=nodejs) were just patched in its latest release. One allowed remote code execution, and two others would have permitted a TLS validation bypass, potentially allowing attackers to bypass checks intended to verify a server’s identity.

In addition, LiteLLM, a popular open source proxy for routing requests to multiple LLM providers, was [compromised](https://www.aikido.dev/blog/litellm-compromised-infostealer-rat) by an attacker who injected malicious code, the company shared [in a post on X](https://x.com/LiteLLM/status/2112945728565993864) on Wednesday afternoon. The malicious artifacts were published to [PyPI](https://pypi.org/project/litellm/) (Python Package Index), [Docker Hub](https://hub.docker.com/), and GHCR (GitHub Container Registry), the post noted.

The malicious code was said to include an information stealer that targeted cloud credentials, passwords, and AI service credentials, in addition to a remote access trojan that could allow hackers to execute commands on compromised systems.

LiteLLM said it has now removed the malicious releases and images and advised anyone who installed them to follow [the remediation guidance](https://github.com/BerriAI/litellm/issues/47826) it provided.

And wait, there’s more! An Indian certificate authority, eMudhra, [had its private keys compromised](https://www.theregister.com/security/2026/10/20/indian-certification-authority-emudhras-private-keys-compromised-one-of-them-was-the-number-4/5304312), potentially allowing attackers to issue fraudulent certificates and impersonate legitimate websites. [Security pros have called this](https://arstechnica.com/security/2026/10/the-internet-goes-on-high-alert-after-discovery-of-8-compromised-tls-certs/) a massive cleanup job and one that’s “bigger than [Heartbleed](https://techcrunch.com/tag/heartbleed/).” (The latter is a reference to the critical security vulnerability in the OpenSSL cryptographic software library).

These issues come on the heels of other security breaches and hacks, including the breach of the cloud-native database-as-a-service, TiDB Cloud, which the [company announced](https://www.pingcap.com/trust-hub/security/security-update-october-2026/) on Monday. Other [hackers](https://www.reddit.com/r/selfhosted/comments/1x9trfc/plex_being_actively_exploited_plex2shell_on_32400/) have been [exploiting](https://thehackernews.com/2026/10/hackers-exploit-plex2shell-flaws-to.html) four patched Plex Media Server flaws, collectively called Plex2Shell. And last week, cybersecurity company [BeyondTrust warned customers](https://www.bleepingcomputer.com/news/security/beyondtrust-patches-zero-day-exploited-in-attacks-since-august/) to patch a critical zero-day in its Remote Support product, which had been exploited since August.

Though the issues were unrelated to each other, their back-to-back arrival highlights the challenges cybersecurity teams now face. This is particularly important as AI could make it easier for attackers to exploit vulnerabilities once discovered.
